# AI Skill Upscaler — Backend (Stage 1)

Multi-tenant FastAPI backend that host LMSs (starting with Moodle) connect to as a plugin.
Stage 1 covers content ingestion (PDF, video transcripts), learners, learning events and a
per-learner activity summary. Embeddings, the AI tutor and any frontend come later.

## Run locally (SQLite, no Docker)

Requires Python 3.11+. Install ffmpeg (`brew install ffmpeg`) if videos will be transcribed.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env              # then set ADMIN_API_KEY
alembic upgrade head              # create / update the schema
uvicorn app.main:create_app --factory --reload
```

Interactive docs: http://localhost:8000/docs. Data goes to `./data/` (SQLite file and uploads).

## Database migrations

The schema is managed only by Alembic (`migrations/`). The app never creates tables. If the
database is not at the latest revision it refuses to start and tells you to migrate.

```bash
alembic upgrade head                                  # or: python -m app.cli migrate
alembic revision --autogenerate -m "describe change"  # after editing app/models.py
alembic check                                         # fails if models and migrations differ
```

Review autogenerated files before committing. Constraint names come from a naming
convention in `app/db.py`, so migrations behave the same on SQLite and Postgres.

## Run with Postgres + pgvector (Docker)

```bash
ADMIN_API_KEY=change-me docker compose up --build
```

This starts `pgvector/pgvector:pg16` (the `vector` extension is enabled at init) and the API on
port 8000. The API container runs `alembic upgrade head` before it starts.
(The compose setup has not been run yet; Postgres was verified on a local Homebrew install, see below.)

### Postgres without Docker

Any Postgres 16+ with pgvector works (Homebrew, Neon, RDS, ...):

```bash
pip install -e ".[postgres]"
export DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST:5432/DBNAME
alembic upgrade head
uvicorn app.main:create_app --factory --reload
```

## Tests

```bash
pytest                                                            # SQLite
TEST_DATABASE_URL=postgresql+psycopg:///upscaler_test pytest      # Postgres
```

The test database is built with the real migrations (`downgrade base` then `upgrade head`)
at session start, and tables are emptied after each test. **Point `TEST_DATABASE_URL` only at
a throw-away database: its contents are wiped.** Tests need no network or API keys. The
ffmpeg tests generate a short clip and are skipped when ffmpeg is not installed.

Verified on 2026-10-28: 53 tests pass on SQLite and on Postgres 18.3 with pgvector 0.8.7
(Homebrew).

## Multi-tenancy and auth

Every source, chunk, learner and event has a `tenant_id`. A tenant is one LMS installation.

1. Create a tenant (the API key is shown once; only its SHA-256 hash is stored):
   ```bash
   curl -X POST localhost:8000/admin/tenants -H "X-Admin-Key: $ADMIN_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{"name": "Demo Moodle", "lms_type": "moodle", "lms_base_url": "https://moodle.example.edu"}'
   ```
   or `python -m app.cli create-tenant "Demo Moodle" --lms-type moodle --lms-base-url https://moodle.example.edu`.
2. Send the key on every call as `X-API-Key`. `GET /tenant` is a cheap connection check for
   a plugin settings page. Rotate with `POST /admin/tenants/{id}/rotate-key`.

Learners are identified by `external_user_id` (the LMS user id), unique per tenant.

## API overview

| Method | Path | Purpose |
|---|---|---|
| POST | `/sources/pdf` | Upload PDF (`file`, optional `title`) → chunks |
| POST | `/sources/video` | Upload video/audio (`file`, optional `transcript` .srt/.vtt, `title`) |
| POST | `/sources/{id}/transcript` | Attach/replace a video's transcript |
| GET | `/sources?kind=&status=` | List sources |
| GET | `/sources/{id}` · `/sources/{id}/chunks` | Source detail · its chunks |
| POST | `/learners` | Create or update a learner by `external_user_id` |
| GET | `/learners` · `/learners/{id}` | List (filter `external_user_id`) · detail |
| GET | `/learners/{id}/activity-summary?since=&until=` | Activity aggregates |
| POST | `/events` | Batch-ingest learning events |
| GET | `/events` | List events (filters: `learner_id`, `event_type`, `since`, `until`) |
| GET | `/xapi/statements` | Same events rendered as xAPI statements |

### Content ingestion

- **PDF**: text is extracted per page with PyMuPDF, then split into 300-word windows with a
  50-word overlap. Windows can cross page boundaries; each chunk stores `page_number` (start)
  and `page_end`. A PDF with no text layer is marked `needs_ocr`.
- **Video**: transcript source, in order of precedence: uploaded `.srt`/`.vtt`, then the
  transcription provider (Whisper when `OPENAI_API_KEY` is set), else status
  `needs_transcript`. Segments are grouped into ~60 s chunks with `start_sec`/`end_sec`.
- **Audio extraction**: before calling Whisper, ffmpeg extracts the first audio track as mono,
  16 kHz, 32 kbps MP3 (`TRANSCRIPTION_AUDIO_BITRATE_KBPS`). That is about 14 MB per hour, so
  only audio longer than ~1 h 45 min is still over OpenAI's 25 MB limit. In that case, or if
  the video has no audio track, the source is marked `failed` with the reason, and a
  transcript can still be attached. If ffmpeg is not found, the original file is sent when it
  is under 25 MB.

Source statuses: `processing`, `ready`, `needs_transcript`, `needs_ocr`, `failed`.
Processing currently runs inside the upload request; move it to a worker queue when uploads
get large.

### Learning events

```json
POST /events
{"events": [{
  "statement_id": "6f1c…",          // optional UUID, reuse it when retrying
  "external_user_id": "moodle-42",  // or "learner_id"; unknown external ids are auto-created
  "event_type": "lesson_complete",
  "occurred_at": "2026-03-02T10:12:00+05:30",
  "session_id": "s-123", "lesson_id": "L1", "topic_id": "T1",
  "content_format": "video",
  "duration_sec": 720, "expected_duration_sec": 600,
  "score": 0.8,
  "properties": {"attempt": 1}
}]}
```

- `event_type`: `session_start`, `session_end`, `lesson_open`, `lesson_complete`,
  `lesson_skip`, `quiz_attempt`, `hint_used`, `video_play`, `video_pause`, `video_seek`,
  `tutor_question`, `reward_earned`.
- `content_format`: `theory`, `video`, `quiz`, `game`, `coding`.
- `score` is scaled 0–1 (xAPI `score.scaled`). Timestamps without an offset are taken as UTC.
- A batch is all-or-nothing. Events whose `statement_id` is already stored count as
  `duplicates`, so retries are safe. Max batch size: `MAX_EVENTS_PER_BATCH` (default 1000).

**xAPI compatibility.** Each event is an xAPI statement: actor = learner
(`account.homePage` = tenant `lms_base_url`, `account.name` = `external_user_id`),
verb = `event_type` (ADL / video profile / TinCan verbs where they exist, custom ones under
`XAPI_BASE_IRI` otherwise; see `app/services/xapi.py`), object = lesson → topic → session,
result = score / duration / completion, context = registration (session UUID), parent topic
and extensions. `GET /xapi/statements` returns a StatementResult, which makes it easy to check
a future Moodle logstore mapping against real data.

### Activity summary

`GET /learners/{id}/activity-summary` (all-time unless `since`/`until` are given):

- `active_hours`: 24 buckets of event counts by hour **in the learner's timezone**
  (default `Asia/Kolkata`), plus `peak_hours`.
- `weekly_activity`: distinct active days per ISO week (Monday start, local time), including
  inactive weeks between the first and last activity; `avg_days_active_per_week`.
- `content_formats`: per format, counts of `lesson_open` / `lesson_complete` / `lesson_skip`,
  `completion_rate` and `skip_rate` (divided by `max(opened, completed + skipped)`; `null`
  with no data), and `avg_duration_ratio` (time spent / expected time on completed lessons).

## Pluggable providers

`app/providers/base.py` defines vendor-neutral `TranscriptionProvider` and `ChatProvider`
interfaces. OpenAI Whisper is implemented over plain HTTP (no vendor SDK). To add a vendor:

```python
from app.providers import register_transcription_provider
register_transcription_provider("my-vendor", lambda settings: MyVendorProvider(...))
```

then set `TRANSCRIPTION_PROVIDER=my-vendor`.

`ADMIN_API_KEY`, `TRANSCRIPTION_PROVIDER`, `OPENAI_API_KEY`, `PDF_CHUNK_WORDS`,

`TRANSCRIPTION_AUDIO_BITRATE_KBPS`, `XAPI_BASE_IRI`, `MAX_EVENTS_PER_BATCH`.

```
  routers/           HTTP endpoints
migrations/          Alembic environment and versions
tests/
```

## Known limitations / next steps

- Ingestion is synchronous; move PDF/transcription work to a background worker.
- No OCR for scanned PDFs. Audio longer than ~1 h 45 min would need splitting into parts
  before transcription.
- Activity summary aggregates in Python; move to SQL or a rollup table at higher volumes.
- Inbound mapping from Moodle's xAPI logstore is not implemented yet (schema is ready for it).
